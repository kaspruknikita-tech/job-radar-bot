# job-radar-bot

Личный Telegram-бот для поиска работы. Каждые 15 минут собирает вакансии из 20+ источников, в том числе с hh.ru, Хабр Карьеры, getmatch, rabota.ru и русскоязычных Telegram-каналов. Оценивает каждую под ваш профиль и присылает в личку только подходящие. Под карточкой кнопки «Откликаюсь / Не подходит / Позже», решения пишутся в Google-таблицу.

Работает без платных API: скоринг идёт по правилам. Если хочется, можно подключить локальную модель (Qwen через Ollama): она отсеивает «чужие» роли по смыслу, а не по словам.

В репозитории лежит пример профиля для Technical PM / Operations / Affiliate в геймдеве, iGaming и martech. Под свою профессию меняется одна папка, `profile/`, код трогать не нужно.

## Чем отличается от research-ux-jobs

Проект вырос из [research-ux-jobs](https://github.com/kaspruknikita-tech/research-ux-jobs), бота-агрегатора вакансий для UX-исследователей.

| | research-ux-jobs | job-radar-bot |
|---|---|---|
| Для кого | сообщество: вакансии публикуются в Telegram-каналы | один человек: карточки приходят вам в личку |
| Профиль | UX/CX-исследователь, зашит в код | любой, настраивается в `profile/` |
| Источники | 11, в основном зарубежные remote-борды | 23 + 5 ATS: упор на русскоязычные и СНГ (hh.ru, Хабр Карьера, getmatch, rabota.ru, geekjob, careerspace, Яндекс, dev.by, vseti, Telegram-каналы) |
| Скоринг | LLM через OpenRouter (платно) | правила + словари профиля, бесплатно; локальная модель по желанию |
| Кнопки | Опубликовать / Отклонить | Откликаюсь / Не подходит (с причиной) / Позже |
| Результат | пост в канале | строка в Google-таблице — ваша воронка откликов |
| Где работает | облако (Railway) | ваш компьютер (Mac, launchd) или любой сервер |

## Как это работает

```
23 источника (каждые 15 мин) + ATS-борды компаний (раз в 6 ч)
        ↓
Фильтр заголовков: WHITELIST / BLACKLIST из профиля, дедупликация
        ↓
Скоринг: заголовок × 2 + плюс-сигналы − минус-сигналы + гео + опыт
        ↓   (необязательно) Qwen: «эта роль про меня?»
Тир S / A / B / C
        ↓
Карточки S/A/B → вам в Telegram       C → лист «Забраковано ботом»
        ↓  [✅ Откликаюсь / ❌ Не подходит / ⏰ Позже]
Google-таблица, лист «Вакансии»
```

Если бот забраковал что-то зря, поставьте «Вернуть» в листе «Забраковано ботом», и вакансия снова придёт в чат.

## Быстрый старт (macOS)

Нужны Python 3.12, PostgreSQL и бот в Telegram.

```bash
# 1. Код и зависимости
git clone https://github.com/kaspruknikita-tech/job-radar-bot.git
cd job-radar-bot
python3.12 -m venv .venv && source .venv/bin/activate
pip install poetry && poetry install

# 2. База
brew install postgresql@16 && brew services start postgresql@16
createdb jobs

# 3. Настройки
cp .env.example .env
```

Откройте `.env` и заполните обязательный блок:

1. `TELEGRAM_BOT_TOKEN` — создайте бота у [@BotFather](https://t.me/BotFather).
2. `TELEGRAM_MODERATION_CHAT` — ваш id: напишите [@userinfobot](https://t.me/userinfobot). Затем отправьте своему боту `/start`, иначе он не сможет вам писать.
3. `DATABASE_URL` — для локальной базы: `postgresql://<ваш-логин-mac>@localhost:5432/jobs`.
4. `GOOGLE_SHEET_ID` — создайте пустую Google-таблицу и возьмите id из ссылки. Затем [создайте сервис-аккаунт](https://docs.gspread.org/en/latest/oauth2.html#for-bots-using-service-account), положите его ключ в `google_credentials.json` в корне проекта и расшарьте таблицу на email сервис-аккаунта с правом редактирования.
5. `HH_CLIENT_ID` / `HH_CLIENT_SECRET` — зарегистрируйте приложение на [dev.hh.ru](https://dev.hh.ru/). Без этого hh.ru отвечает 403.

Запуск:

```bash
python bot_app.py
```

Через минуту начнётся первый цикл, карточки пойдут по мере обхода источников. Полный цикл занимает 20–25 минут.

## Настройка под себя

Вся настройка — две вещи в папке `profile/`:

| Файл | Что в нём |
|---|---|
| `profile/profile.py` | что искать, что отсеивать и как считать баллы |
| `profile/role-profile.md` | шаблон: описание вас человеческим языком для локальной модели (необязательно) |

Чтобы держать профиль вне репозитория, скопируйте папку куда угодно и укажите путь в `PROFILE_DIR` в `.env`.

### profile.py по разделам

**1. Что искать.** Поисковые запросы для каждого источника: `SEARCH_HH`, `SEARCH_HABR_CAREER`, `SEARCH_LINKEDIN` и т.д. Сюда вписываются названия вашей роли на русском и английском. `SEARCH_HH_AREAS` — регионы hh.ru (1 — Москва, 2 — Санкт-Петербург, 113 — вся Россия).

**2. Фильтр заголовков.** Решает, попадёт ли вакансия в базу вообще.
- `WHITELIST` — начала слов, которые должны быть в заголовке: `"проект"` поймает «проектов» и «проектами».
- `BLACKLIST` — стоп-роли, проверяются первыми.

**3. Словари скоринга.**
- `TITLE_STRONG` — пары `(фраза, вес)`: чем ближе заголовок к вашей роли, тем больше вес (0–45).
- `TITLE_BAD` — если слово есть в заголовке, это сразу тир C.
- `DESC_POS` / `DESC_NEG` — слова в описании, которые прибавляют или отнимают баллы: ваш домен, инструменты, красные флаги вроде «холодные звонки».

**4. Архетипы и домен.**
- `ARCHETYPES` — ваши направления (например TPM / OPS / DEL). По ним вакансия получает баллы, даже если заголовка нет в словаре.
- `DOMAIN` — индустрии, в которых у вас опыт.
- `HOME_CITY` / `SECOND_CITY` / `RELOC_COUNTRIES` — города и страны.

**5. География.** `GEO_POINTS` — сколько баллов дать за удалёнку, гибрид, ваш город, другой город или релокацию.

Итоговые пороги тиров задаются в `scoring/tier_mapper.py`: S от 130, A от 95, B от 65. Если ваши словари дают баллы в другом масштабе, подвиньте пороги.

### Как проверить, что профиль работает

Не нужно ждать цикла. Вставьте описание любой вакансии:

```bash
pbpaste | python scripts/try_profile.py "Technical Project Manager" --format Удалёнка
```

```
Фильтр заголовков: пропущена
Тир S (curated_plus), баллы 161, архетип TPM, гео remote_ru
   +90  заголовок
   +46  сигналы
   +25  гео
сигналы: мобильных игр, api, интеграц, sla · удалёнка
```

Порядок работы: 5–10 вакансий, которые вам точно подходят, и 5–10, которые точно нет. Прогоните их и правьте словари, пока первые не окажутся в S/A, а вторые в C.

После правки профиля бота нужно перезапустить.

### Локальная модель (необязательно)

Правила не отличают «руководителя отдела продаж, у которого в описании CRM» от партнёрской операционки: разница смысловая. Для таких случаев есть Qwen:

```bash
brew install ollama && ollama pull qwen3:8b
```

В `.env` поставьте `LLM_ROLE_ENABLED=true`. Затем заполните шаблон `profile/role-profile.md`: кто вы, какие роли точно не ваши и, главное, как разбирать пограничные случаи. Модель выдаёт только вердикт «моё / не моё», баллы по-прежнему считает код.

Учтите скорость: на M1 с 16 ГБ это 20–30 секунд на вакансию.

### ATS-совпадение (для продвинутых)

Бот умеет сравнивать требования вакансии с вашим опытом и показывать в карточке совпадения и пробелы. Для этого нужна папка с описанием опыта в формате автора: блоки опыта с тегами, `manifest.md` и `core.md`. Путь к ней указывается в `CAREER_DATA_DIR`. Формат смотрите в `scoring/career_os.py`.

Без этой папки ATS-часть просто выключена, всё остальное работает. `profile/career/` добавлена в `.gitignore`, чтобы личные данные не попали в git.

## Постоянная работа на Mac

Чтобы бот стартовал при входе в систему и перезапускался после падения, используйте launchd. Создайте файл `~/Library/LaunchAgents/com.job-radar.plist`:

```xml
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN" "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0">
<dict>
    <key>Label</key><string>com.job-radar</string>
    <key>WorkingDirectory</key><string>/ПУТЬ/К/job-radar-bot</string>
    <key>ProgramArguments</key>
    <array>
        <string>/usr/bin/caffeinate</string><string>-is</string>
        <string>/ПУТЬ/К/job-radar-bot/.venv/bin/python</string><string>bot_app.py</string>
    </array>
    <key>RunAtLoad</key><true/>
    <key>KeepAlive</key><true/>
    <key>StandardOutPath</key><string>/tmp/job-radar.log</string>
    <key>StandardErrorPath</key><string>/tmp/job-radar.log</string>
</dict>
</plist>
```

```bash
launchctl load ~/Library/LaunchAgents/com.job-radar.plist          # включить
launchctl kickstart -k gui/$(id -u)/com.job-radar                  # перезапустить после правок
```

`caffeinate -s` не даёт Mac уснуть, но только от сети. На батарее с закрытой крышкой Mac спит, и сбор встаёт до пробуждения. Если цикл завис дольше 2 часов, встроенный сторож перезапускает процесс.

## Ограничения

- Парсеры читают публичные страницы и API сайтов. Сайты меняют вёрстку, и отдельный источник может перестать работать; остальные продолжат.
- Бот рассчитан на личное использование. Не публикуйте собранные вакансии массово: у части сайтов это запрещено правилами.
- LinkedIn с серверного IP блокирует запросы, там нужны прокси (`JOBSPY_PROXIES`). С домашнего IP работает без них.
